集計方法・判断基準

1. 投稿スコア

モデルは投稿を次の3種類として評価します。

  • NOT: 攻撃的ではない
  • GRY: グレーゾーン・文脈依存
  • OFF: 攻撃的と推定される

モデルの出力を3クラスの比率に正規化し、次の式にします。

offensive_score = P(OFF) + 0.35 × P(GRY)

例えば P(OFF)=0.60、P(GRY)=0.20 なら、投稿スコアは 0.60 + 0.35×0.20 = 0.67 です。OFF はそのまま加点し、GRY は攻撃性を断定できないため35%だけ反映します。NOT は加点しません。

この値は「投稿が攻撃的である確率」そのものではなく、モデル出力を使った観測用の相対スコアです。0.70 を超えたから自動的に違反・有害と決めるものではありません。

スコアの分散・起伏

標準偏差は各投稿スコアが平均からどれだけ離れているかの平均的な大きさです。高いほど、低スコア投稿と高スコア投稿が混在し、投稿ごとの起伏が大きい傾向を示します。ただし、極端な1件の影響を受けやすい指標です。

IQR（四分位範囲）は、スコアの中央50%に入る範囲で、第75百分位 − 第25百分位 です。高いほど通常時の投稿にもばらつきがあります。標準偏差より外れ値に頑健なので、両方が高い場合に「全体的に起伏が大きい」と解釈しやすくなります。

例えば平均が低く標準偏差だけ高い場合は、普段は低スコアだが一部に極端な投稿がある可能性があります。これは単発投稿を理由にアカウント全体を断定するものではなく、必ず投稿数とconfidence、上位・下位の実例を併せて確認します。

2. アカウント集計

投稿スコアを平均するだけでは、少数の極端な投稿や一度だけのバズに引っ張られます。そのため、複数の統計量を使います。

  • mean: 対象投稿全体の平均。継続的な水準を見る。
  • p90: スコアの高い方から10%を除いた境界。上位投稿の多さを見る。
  • p95: 高い方から5%を除いた境界。極端な投稿が繰り返されているかを見る。
  • max: 最大値。最も高い投稿を示すが、単独ではアカウント全体の根拠にしない。
  • high score rate: 投稿スコア ≥ 0.70 の投稿割合。

現在の暫定 account-v1 は次の式です。

ObservedBehaviorScore = 0.35×mean + 0.40×p95 + 0.25×high_score_rate

重みの意味は、通常時の水準（35%）、繰り返し現れる高スコア投稿（40%）、高スコア投稿の頻度（25%）です。p95 を最大値より重くしているのは、一度だけの極端な投稿による過大評価を抑えるためです。これらの重みと0.70という閾値は仮説値であり、今後の人手ラベルで校正します。

3. リポストの扱い

単純リポストは本人の文章とは限らないため account score から除外します。引用リポストは本人のコメントが付いている可能性があるため含めます。両方とも取得記録としては残し、単純リポスト率も別途確認できるようにします。

4. confidence

confidence はモデルの正しさではなく、集計に使った投稿数の目安です。

  • very_low: 20件未満。傾向判断には不十分。
  • low: 20〜49件。参考値。
  • medium: 50〜99件。一定の傾向を確認できるが、まだ不確実。
  • high: 100件以上。サンプル数の面では安定するが、モデル誤判定がなくなるわけではない。

5. 解釈上の注意

このダッシュボードは、観測期間中の公開投稿に見られた攻撃的・炎上的な行動の強度と頻度を整理するものです。人格、思想、国籍、属性、犯罪性、危険人物性を判定しません。政治・選挙関係アカウントは account-level ranking の対象外にします。

モデル

TomokiFujihara/twhin-bert-base-japanese-offensiveness-estimation。CPU の batch 推論を使用します。モデルカードの評価値は NOT / GRY / OFF の分類性能であり、実際の X 投稿では皮肉、引用、文脈、自虐、ニュース転載などの誤判定が起こり得ます。最終的な確認には高スコア投稿と通常投稿の両方を人間が確認してください。

公開時の注意: 生ポスト文やプロフィール情報を公開せず、原則 tweet ID / user ID と派生集計値に限定してください。X の最新ポリシー、利用規約、法令、研究倫理要件を確認してください。

レビュー結論

条件付きで妥当とします。ただし、これはX全体の無作為標本でも、炎上全体の代表標本でもありません。話題層・期間・検索語・検索結果に条件づけた探索用seed標本です。したがって、アカウントの人格や危険性を推定する母集団として扱わず、公開投稿行動の探索範囲を広げるためにのみ使います。

敵対的レビューで確認した弱点と対策

  • 露出上位の選択は人気バイアスを生む。 view数や反応数の上位だけをseedにすると、大規模アカウント・著名話題に偏る。対策として、話題層と期間ごとに候補を作り、低・中・高反応の層を分け、各層から採用する。
  • 検索結果は無作為ではない。 X検索の順位は検索語・時刻・表示条件に依存する。対策として、検索語、期間、取得時刻、ページ範囲、抽出乱数seedを保存し、完全無作為とは表現しない。
  • ログインアカウント由来の観測バイアスがある。 取得には wangoroge333 を利用しているため、X側のパーソナライズ、地域・言語設定、アカウント状態、表示制限によって、検索結果・表示順位・取得可能な関係が変わる可能性がある。このアカウントで得た結果をX全体の分布とはみなさず、取得アカウントと観測条件を記録する。
  • 炎上元と攻撃的反応を混同する。 炎上投稿への反応の全てが攻撃的とは限らない。対策として、元投稿、返信、引用、単純リポストを別扱いにし、非炎上比較seedも含める。
  • 話題リスト自体が既存研究の偏りを継承する。 政治・医療などに集中し得る。対策として、生活・商品・娯楽・自然な比較対象を含む層化表を事前固定し、各層の件数を報告する。
  • 単一seedの到達範囲を一般化できない。 最初のseedでは約70前後のアカウントが得られたが、これはその会話ネットワーク固有の結果である。対策として複数seedを独立checkpointで走らせ、seed別の到達数を分離する。
  • 反応規模とインプレッションは同じではない。 view数が欠落する場合は、公開反応から作るexposure proxyと明記し、view数そのものと混ぜない。

確定したseed選定手順

  1. 話題層を事前に固定する。
  2. 各層について複数の検索語セットを作る。
  3. ランダムに期間・時間窓を選ぶ。
  4. 公開・日本語・単純リポスト除外など、事前に記録した条件で候補を取得する。
  5. 候補ページ内から一定規則で抽出し、検索順位そのものを採用理由にしない。
  6. 同一会話、同一投稿者、重複投稿を整理する。
  7. 低・中・高反応の層から均等に候補を残す。
  8. view数があれば保存し、なければexposure proxyとして別名で保存する。
  9. 採用・除外理由をseed台帳へ保存する。
  10. seedごとにv2を独立実行し、10アカウント×100投稿単位で報告する。

追加記録: 実装・研究設計の変更履歴（時系列）

以下は、実際に確認できる実装状態と作業記録を分けて記載した変更履歴です。後から追加した説明を、当初から存在した仕様として扱わないための記録です。

  1. 単一seedの初期試行: 2099783355248341399 を作為的に選び、1投稿から周辺関係を取得した。これは探索器の到達規模を測る試行であり、無作為抽出でも代表標本でもない。
  2. 初期取得・分析: アカウントの公開プロフィールと投稿を保存し、最新投稿を最大100件取得して投稿スコア・account score・evidenceを計算した。この段階では単一seedのネットワークに強く依存していた。
  3. ブラウザ取得の導入: プロフィールの実投稿をブラウザ経由で収集し、単純リポストはaccount scoreの対象から除外、引用リポストは残す方針にした。取得記録と分析対象を分けた。
  4. 探索v2への途中切替: 既存checkpointを破棄せず、処理済み起点・待機列・深度を引き継ぎ、候補投稿から次の起点を追加する方式へ切り替えた。したがって、v2以前とv2以後の結果は同一条件の実験ではない。
  5. 単一seed結果の確認: 単一seedから約70前後のアカウントに到達したが、これは会話固有の到達数であり、X全体の推定には使えない。v2再実行では追加7アカウントを確認した後、新規0件が複数サイクル続いた。
  6. seed選定の再設計: 単一seedの作為性と供給枯渇を受け、話題層、ランダムな期間窓、検索語、低・中・高露出層、非炎上比較対象、採用理由を事前記録するseed探索プロトコルを追加した。
  7. 実装上の制約: X検索には完全なランダム順やインプレッション順指定がないため、実装は完全無作為抽出ではなく、検索結果内の再現可能な層化抽出である。またログイン観測アカウント wangoroge333 によるパーソナライズ・表示制限の影響が残る。
  8. 公開範囲の分離: ローカルDB・取得処理・cookieは公開せず、公開PagesにはIDリンク版とX公式ウィジェット版、集計式、限界、変更履歴のみを配置した。

現時点の解釈: seed生成プロトコルは、探索範囲を広げるためのサンプリング枠としては妥当だが、代表性・因果性・人格判定を保証しない。seed別の到達数、重複率、取得不能率、話題層別の件数を併記して評価する。
